# SeatOps 완료 조건과 학습 확인

상태: **계획 단계. 아래 기능은 모두 미완료입니다.** 진단 풀이와 설계 문서의 존재는 파이프라인 구현 완료를 뜻하지 않습니다.

체크하려면 학습자가 직접 작성·실행한 코드, 테스트 결과, 본인의 설명이 모두 필요합니다. 로컬 검증과 실제 AWS 검증은 분리합니다.

## Phase 1: SeatOps 자체 완성

AWS 없이 구현·검증할 서비스 범위입니다.

| 완료 체크 | 기준 | 필요한 증거 | 설명할 질문 |
|---|---|---|---|
| [ ] | Python·SQL 현재 수준 확인 | 기존 진단 풀이·실행 결과·미응답 진단 답 | 입력 변경 여부와 SQL 집계 결과를 설명할 수 있는가? |
| [ ] | 재현 가능한 이벤트·JSONL 생성 | 같은 seed+기준 날짜 비교 테스트 | 재현성을 깨는 값은 무엇인가? |
| [ ] | Raw 원본 보존 | 입력 파일과 저장 원본 비교 | JSONB와 원본 보존은 같은가? |
| [ ] | 중복 적재 방지 | 같은 파일 2회, 다른 파일의 같은 이벤트 테스트 | 어떤 키로 무슨 중복을 막는가? |
| [ ] | 정상/오류 분리 | 정상·필수값 누락·형식 오류 fixture와 테스트 | 오류가 Staging에 들어가지 않는 근거는? |
| [ ] | Mart 생성 | 계산식을 정한 SQL과 기대 결과 테스트 | Grain, 날짜 기준, 성공률 분모는? |
| [ ] | 오류 수정 재처리 | 원본 유지·수정 이력·반복 수정 테스트 | 원본을 덮어쓰면 무엇을 잃는가? |
| [ ] | 로컬 Compose 전체 흐름 | 생성→적재→검증→집계 실행 기록 | 이미지·컨테이너·volume의 차이는? |
| [ ] | 부분 실패와 재시작 | 중간 실패·강제 종료·DB 재시작 전후 비교 | 어느 변경이 commit되고 rollback되는가? |
| [ ] | 로컬 실행 이력·로그 | 성공/실패·입력/처리/오류/중복 건수 기록 | 데이터 오류와 배치 실패는 어떻게 다른가? |
| [ ] | 기본 GitHub Actions CI | pytest·이미지 빌드 check 실행 URL | 잘못된 코드 변경을 어떻게 찾는가? |
| [ ] | 로컬 재현 문서 | 실행 README·본인 결정 기록 | AWS 없이 다른 사람이 실행할 수 있는가? |

**전부 확인되면 SeatOps 로컬 MVP 완성으로 기록합니다.** 코드·테스트뿐 아니라 본인의 설명까지 확인해야 Phase 2를 시작합니다.

## Phase 2: AWS 배포와 운영

완성한 서비스를 배포하며 확인할 범위입니다.

| 완료 체크 | 기준 | 필요한 증거 | 설명할 질문 |
|---|---|---|---|
| [ ] | Terraform 구성 검증 | fmt·validate·모의 테스트 | state와 변수·실제 리소스의 차이는? |
| [ ] | 실제 AWS 생성 | 승인받은 plan/apply와 리소스 확인 | 왜 각 리소스가 필요한가? |
| [ ] | EC2에서 동일 이미지 실행 | SSM 접속 및 앱 실행 기록 | 로컬과 EC2 이미지 아키텍처가 맞는가? |
| [ ] | S3 원본으로 실제 처리 | 업로드·읽기·DB 집계 증거 | 역할 권한이 어디까지 허용되는가? |
| [ ] | 보안 접근 제어 | S3 공개 차단, SG·IAM 검사와 실제 접근 확인 | DB가 인터넷에서 접근 불가능한 이유는? |
| [ ] | CloudWatch 실행·오류 관측 | 성공/실패 로그·시각·실행 식별자 | 데이터 오류와 배치 실패는 어떻게 다른가? |
| [ ] | 인프라 CI 확장 | Terraform 검증 check와 배포 차단 절차 | 기존 서비스 CI에 무엇을 추가했는가? |
| [ ] | 비용·정리 | 요금 확인 기록·백업·승인된 삭제·잔존 리소스 확인 | EC2 stop 후에도 비용이 남는 항목은? |
| [ ] | 포트폴리오 문서 | 본인 ADR·실패/복구 기록·증거가 연결된 README | 직접 해본 것과 AI 도움을 받은 범위를 구분하는가? |

## 과제 하나의 통과 조건

1. 학습자가 초안을 먼저 제출한다.
2. 리뷰의 문제점을 직접 수정한다.
3. 정상 사례와 해당 기능에 필요한 잘못된 입력·중복·실패 테스트를 실제 실행한다.
4. 명령 출력과 기대 결과를 비교한다.
5. 개념 질문 2~3개에 자기 말로 답한다.

하나라도 확인되지 않으면 다음 과제로 넘어가지 않습니다. AI가 대신 작성한 코드의 테스트 통과를 학습자의 숙련 완료로 처리하지 않습니다.

## 페이즈별 완료 판정

- **SeatOps 로컬 MVP 완성:** Phase 1의 코드·테스트·본인 설명을 모두 확인한 상태. AWS 없이도 독립적인 완료 지점이다.
- **AWS 배포·운영 학습 완료:** Phase 2의 실제 배포·로그·권한·복구·비용 정리 증거까지 확인한 상태.

AWS 승인이 없거나 환경이 준비되지 않았으면 ‘Phase 1 완료 / Phase 2 미진행’으로 구분한다. Phase 1의 미완료 기능을 Phase 2로 넘기지 않고, 일정이 끝났다는 이유로 완료 표시하지 않는다.

ECR 자동 CD, Airflow, RDS, 고가용성은 이번 필수 완료 기준에 포함하지 않습니다. 필요성이 확인되면 별도 계획과 완료 기준을 작성합니다.
